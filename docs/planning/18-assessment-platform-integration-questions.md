# أسئلة الربط مع منصة المقاييس

تاريخ التحديث: 4 أكتوبر 2026. الحالة: أسئلة جاهزة لمبرمج المنصة، وليست عقد API معتمدًا. المشروع ما زال في التخطيط.

**قرار المستخدم:** منصة المقاييس موجودة بالفعل، ويُخطط لإطلاقها خلال هذا الأسبوع بحسب إفادته. المطلوب ربطها بالتطبيق، ويمكن الحصول على التفاصيل من مبرمجها. لا نعيد بناء منصة المقاييس ضمن مطمئن. اسم المنصة ورابطها وإمكاناتها التقنية لم تُقدَّم بعد؛ موعد الإطلاق إفادة من المستخدم وليس نتيجة تحقق تقني.

## رسالة قابلة للإرسال إلى مبرمج المنصة

نحتاج ربط منصة المقاييس بتطبيق مطمئن وخادمه، وعرض النتائج للمريض والأخصائي وفق صلاحياتهما. فضلاً تزويدنا بالتالي، مع أمثلة ببيانات تجريبية:

1. **التوثيق والبيئات:** اسم المنصة وروابطها، وثائق API بصيغة Swagger/OpenAPI أو Postman، إصدار API، وروابط بيئتي الاختبار والإنتاج. هل APIs جاهزة الآن؟ وما العمليات غير المتاحة أو التي تحتاج تطويرًا؟
2. **المصادقة والدخول الموحد:** طريقة مصادقة خادم مطمئن، والصلاحيات المطلوبة، وتجديد/إلغاء التوكنات. هل تدعمون SSO بحيث يدخل المريض دون حساب أو كلمة مرور إضافية؟ ما البروتوكول، ومدة صلاحية رابط الدخول، وطريقة الرجوع للتطبيق؟ تُسلَّم بيانات الوصول عبر قناة آمنة، لا داخل هذه الوثيقة.
3. **ربط الهوية:** كيف ننشئ أو نربط مستخدمًا موجودًا؟ هل يمكن حفظ معرف مطمئن الخارجي؟ كيف نمنع الحسابات المكررة؟ نحتاج فصل صاحب الحساب والدافع عن المريض المستفيد، خصوصًا عند حجز مقياس لأحد أفراد الأسرة، وعدم الاعتماد على رقم جوال الأسرة وحده.
4. **قائمة المقاييس:** API لقائمة المقاييس ومعرفاتها وإصداراتها، الاسم والوصف بالعربية والإنجليزية، الفئات العمرية/الأهلية، المدة، الأسعار إن وجدت، عدد المحاولات، وتعريف حالات التوفر أو إيقاف المقياس.
5. **طلب المقياس:** API لإنشاء طلب أو إسناد مقياس لمريض، وربطه بالأخصائي الطالب ومعرف طلب مطمئن. هل يمكن للمريض شراء المقياس مباشرة؟ نحتاج أمثلة لإلغاء الطلب، انتهاء صلاحيته، واستئنافه، مع مفتاح يمنع تكرار الطلب عند إعادة المحاولة.
6. **طريقة فتح المقياس:** هل لديكم SDK أو واجهة قابلة للتضمين، أم رابط آمن يفتح في متصفح خارجي/WebView؟ ما الدعم الفعلي لـ Flutter على iOS/Android وللموقع، والعربية/الإنجليزية وRTL؟ كيف يعمل حفظ التقدم والعودة بعد إغلاق التطبيق أو انقطاع الاتصال؟ هذه بدائل نحتاج تقييمها، وليست طريقة مختارة مسبقًا.
7. **الدفع والاستحقاق:** من يستقبل الدفع ومن يصدر الفاتورة؟ هل يستطيع مطمئن منح الوصول بعد الدفع دون تحصيل ثانٍ في منصة المقاييس؟ كيف تُلغى صلاحية الطلب عند الاسترداد؟ وما التعامل مع إعادة المحاولة، الطلب المجاني، أو المقاييس المدفوعة سابقًا؟
8. **الحالات والأحداث:** حالات الطلب والمحاولة، وأحداث البدء/الإكمال/الفشل/الإلغاء. هل توجد Webhooks موقّعة؟ نحتاج طريقة التحقق، معرف الحدث، إعادة الإرسال، التعامل مع التكرار والأحداث غير المرتبة، وAPI للاستعلام أو المزامنة عند فقد حدث.
9. **النتائج والتقارير:** أمثلة JSON للدرجات والنتيجة والتفسير وإصدار المقياس ووقت الإكمال، وAPI للتقرير/PDF إن وجد. هل تتاح الإجابات التفصيلية أم النتائج فقط؟ هل توجد نتائج تحتاج مراجعة أو اعتمادًا؟ وكيف تُبلّغون تعديل النتيجة بعد نشرها؟ ما اللغات المتاحة؟
10. **صلاحيات النتائج:** كيف يقتصر الوصول على المريض المعني والأخصائي المخوّل؟ هل يمكن تعطيل وصول أخصائي انتهى تكليفه أو فرد خرج من الأسرة؟ وهل روابط التقارير مؤقتة ومحمية؟ مشاركة الباقة لا تمنح تلقائيًا الوصول للتقرير الطبي.
11. **البيانات والاحتفاظ:** الحقول الشخصية المطلوبة فقط، موقع معالجة وتخزين البيانات، الجهات الفرعية التي تصل إليها، آلية الموافقات، سياسة الاحتفاظ/الحذف والتصدير، وسجلات الوصول. نحتاج معرفة ما يبقى لدى المنصة وما يحفظه مطمئن من نتائج أو ملفات.
12. **التشغيل والاختبار:** حدود الطلبات وحجم الصفحات، الأخطاء وصيغتها، مهلات الاتصال، التوافر والدعم، سياسة تغيير الإصدارات، وحسابات اختبار للمريض والأخصائي. نحتاج تجربة كاملة تشمل أسرة، نتيجة مكتملة، إعادة طلب/حدث مكرر، انقطاع اتصال، ونتيجة معدلة.

## ما نحتاج استلامه أولًا

- رابط المنصة ووثائق API.
- بيئة وحسابات اختبار، وآلية آمنة لتسليم وصول الخادم.
- مثال كامل: ربط مريض ← طلب مقياس ← فتحه ← إكماله ← إشعار ← جلب النتيجة والتقرير.
- تحديد مسؤولية الدفع والفاتورة، واختيار طريقة الدخول والعرض بعد التحقق من الدعم.

**توصية للتطوير لاحقًا:** يتولى خادم مطمئن أسرار الربط والتحقق من الأحداث وصلاحيات المريض والأخصائي. لا يُعتمد نجاح رابط الرجوع وحده كدليل على الدفع أو الإكمال، ولا تُوضَع بيانات سرية أو تفاصيل طبية في الروابط. تفاصيل البروتوكول والعقود تبقى مفتوحة حتى يرد مبرمج المنصة.
